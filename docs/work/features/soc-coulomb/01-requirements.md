## 0. 约定与单位基线（与 `types.h` 一致）

| 量 | 单位 | 符号约定 | 来源 |
|---|---|---|---|
| 电压 | mV | — | `bms_cell_meas.cell_mv[]` (int32) |
| 总电流 | mA | **充电为正**，放电为负 | `bms_cell_meas.pack_current_ma` (int32) |
| 温度 | 0.1℃ | — | `bms_cell_meas.temp_dci[]` (int32) |
| 时间戳 | ms | `k_uptime`，单调递增，`uint32` 会回绕 | `bms_cell_meas.timestamp_ms` (uint32) |
| SOC | ‰（千分比） | 0..1000 | `bms_soc.soc_permille` (uint16) |
| 缺省采样周期 | ms | 合理性基准 | `CONFIG_BMS_AFE_SAMPLE_PERIOD_MS`（当前 100） |

约定：
- 本特性所有时间差、电荷增量计算均以上表单位为准，需求中数值一律带单位。
- 电荷转移方向与电流符号一致：充电（电流为正）→ SOC 增大；放电（电流为负）→ SOC 减小。
- 「失效安全相关」需求以 **⚠️** 标注；SOC 为非安全关键信息流，红线是「不污染、不拖累」安全链。

EARS 句式说明：普遍「系统应…」；事件「当…时，系统应…」；状态「在…期间，系统应…」；不期望「如果…，则系统应…」。本文中“系统”特指 **SOC 估算模块**。

## 1. 功能需求清单

### REQ-SOC-C01　库仑积分核心（安时积分）
- **EARS（事件）**：当 SOC 模块收到一帧有效电芯测量 `bms_cell_meas` 时，系统应以该帧 `pack_current_ma`（mA，充电为正）与相邻两帧之间的时间间隔 Δt（ms）为基础，按电流对时间积分累计转移电荷量，并据此更新 SOC 估值。
- **理由**：电压线性映射在 LFP 平台期严重失真；安时积分提供短期高精度 SOC，是后续混合估算与可用能量上报的基础（迭代计划 §1）。
- **验收准则**：
  1. 给定恒定电流 I（mA）持续 T（ms），换算的转移电荷量应等于 `I × T`（量纲 mA·ms），换算为 mAh 后与解析值误差 ≤ 1 个 SOC 最小可表示步进（1‰）。
  2. 给定额定容量 C（mAh），恒流 I（mA）持续时间 T（ms）后，SOC 增量应满足 `ΔSOC(‰) ≈ (I × T) / (3600 × C) × 1000`，相对误差 ≤ ±1‰（在不触发夹紧的区间内）。
  3. 电流为正时 SOC 不减小，电流为负时 SOC 不增大（方向正确性，呼应 REQ-SOC-C07）。

### REQ-SOC-C02　时间间隔来源与异常处理
- **EARS（事件）**：当系统计算相邻两帧时间间隔 Δt 时，系统应优先取本帧与上一帧 `timestamp_ms` 的差值；当该差值不可用或不合理时，系统应回退到 `CONFIG_BMS_AFE_SAMPLE_PERIOD_MS`（ms）作为 Δt。
- **EARS（不期望）**：如果本帧 `timestamp_ms` 小于或等于上一帧（时间戳非单调/回绕），则系统应判定 Δt 不可信，回退到缺省周期，并不得据此产生负的或异常的时间间隔。
- **理由**：`timestamp_ms` 为 `uint32` 的 `k_uptime`，存在首帧无前序、丢帧、回绕/非单调风险（迭代计划 §4 R2）。
- **验收准则**：
  1. 首帧（无前序时间戳）不进行积分（见 REQ-SOC-C04），或以缺省周期作为 Δt，二者择一但须可被测试确定地验证。
  2. 当帧间差为 0 或负值时，使用的 Δt 等于 `CONFIG_BMS_AFE_SAMPLE_PERIOD_MS`，且 SOC 不出现反向跳变。
  3. 当帧间差异常大（丢帧，定义为 > N × 缺省周期，N 由设计阶段给出且默认建议 N=10）时，Δt 被夹紧到合理上限或回退到缺省周期，避免单帧产生不合理的大幅 SOC 跳变（单帧 |ΔSOC| ≤ 设计给定上限）。

### REQ-SOC-C03　SOC 夹紧到 [0, 1000]‰
- **EARS（普遍）**：系统应在每次更新后将 `soc_permille` 夹紧在闭区间 [0, 1000]‰ 内，发布值不得越界。
- **理由**：积分累计可能驱动估值超出物理范围；`bms_soc.soc_permille` 为 `uint16`，越界将语义错误（迭代计划 §2 C03）。
- **验收准则**：
  1. 持续充电直至饱和后，`soc_permille` 稳定于 1000‰，不溢出、不回绕。
  2. 持续放电直至耗尽后，`soc_permille` 稳定于 0‰，不出现负值或 `uint16` 下溢。
  3. 任意输入序列下，发布的 `soc_permille` 始终满足 `0 ≤ soc_permille ≤ 1000`。

### REQ-SOC-C04　上电初始化策略
- **EARS（状态）**：在上电后尚无库仑积分历史期间，系统应对 SOC 进行一次性初始化，初值由首帧测量的电压映射（沿用现有线性映射，3000mV→0‰、4200mV→1000‰）确定，并将其作为后续积分的起点。
- **理由**：库仑计数为相对量，初值错误将长期带偏移；本迭代用一次性电压映射初始化，OCV 精确标定列为后续非目标（迭代计划 §1 非目标、§4 R3）。
- **验收准则**：
  1. 上电后首次得到有效测量时，`soc_permille` 等于由该帧平均电压经现有线性映射并夹紧后的值（与现桩实现一致，误差 0‰）。
  2. 初始化仅发生一次；其后各帧均以库仑积分更新，不再被电压映射覆盖。
  3. 初值同样满足 [0, 1000]‰ 夹紧（REQ-SOC-C03）。

### REQ-SOC-C05　发布到 `chan_soc` 的触发条件
- **EARS（事件）**：当系统成功完成一帧 SOC 更新（含初始化帧）时，系统应将更新后的 `bms_soc`（含 `soc_permille`、`soh_permille`、`timestamp_ms`）发布到 `chan_soc`。
- **EARS（普遍）**：系统发布的 `bms_soc.timestamp_ms` 应等于触发本次更新的测量帧的 `timestamp_ms`，`soh_permille` 应保持 1000‰（本迭代 SOH 为非目标）。
- **理由**：SOC 上报服务于 comm 上报与 balancing 决策；时间戳对齐便于下游关联（迭代计划 §1、§2 C05、非目标）。
- **验收准则**：
  1. 每次有效更新对应且仅对应一次 `chan_soc` 发布。
  2. 被跳过的帧（见 REQ-SOC-C06）不产生发布，或发布上一稳定值之一（择一，须由设计确定并可测）。
  3. 发布的 `timestamp_ms` 与输入帧一致；`soh_permille == 1000`。

### REQ-SOC-C07　电流符号与积分方向一致性
- **EARS（普遍）**：系统应保证积分方向与 `pack_current_ma` 符号约定一致——充电（> 0）使 SOC 单调不减，放电（< 0）使 SOC 单调不增，零电流（== 0）不改变 SOC（除夹紧外）。
- **理由**：符号反转会导致 SOC 反向，是高发缺陷（迭代计划 §4 R6）。
- **验收准则**：
  1. 输入恒正电流序列，SOC 序列单调不减（直至夹紧到 1000‰）。
  2. 输入恒负电流序列，SOC 序列单调不增（直至夹紧到 0‰）。
  3. 输入 `pack_current_ma == 0` 的帧，SOC 不变（时间戳照常更新）。

## 2. ⚠️ 失效安全相关需求（单独标注）

> 项目级红线：默认接触器 OPEN，仅判定 NORMAL 才 CLOSED；安全相关线程优先级更高。SOC 为非安全关键信息流，须「不污染、不拖累」安全链（迭代计划 §4）。

### ⚠️ REQ-SOC-C06　异常数据隔离与安全降级
- **EARS（不期望）**：如果一帧测量被判定为坏数据（包括但不限于：`meas`/`out` 为空指针、时间戳非单调/回绕、`pack_current_ma` 超出合理量程、帧间间隔异常大），则系统应安全降级——跳过本帧积分或对增量进行合理性夹紧，绝不让单帧异常导致 SOC 大幅跳变或越界。
- **理由**：库仑计数存在累计漂移与坏数据敏感性；坏数据若直接进入积分会误导上层（迭代计划 §4 失效安全 3、R1/R2）。
- **验收准则**：
  1. 输入空指针返回错误码（负 errno）且不发布、不更新内部状态。
  2. 注入时间戳非单调、超量程电流、异常大间隔的单帧后，SOC 单帧 |ΔSOC| 不超过设计给定上限，且仍满足 [0, 1000]‰。
  3. 异常帧不得导致内部累计电荷状态被污染到无法恢复（后续正常帧能继续正确积分）。

### ⚠️ REQ-SOC-C08　SOC 不参与接触器/保护决策（边界声明）
- **EARS（普遍）**：系统估算的 SOC 应仅作为信息量上报，不得作为过充/过放/接触器开合的判据；过充、过放、过流、过温保护仍由 protection 模块基于电压/电流/温度独立判定。
- **理由**：库仑计数漂移不可作为安全保护唯一依据；明确职责边界防止误用（迭代计划 §4 失效安全 1）。
- **验收准则**：
  1. SOC 模块的输出通道仅为 `chan_soc`；不向保护/接触器相关通道发布任何控制语义数据。
  2. 需求与后续设计文档中明确记载此边界，评审确认。

### ⚠️ REQ-SOC-C09　不阻塞安全链（实时性约束）
- **EARS（普遍）**：在任何输入/背压条件下，系统都不得以无限等待方式阻塞 zbus 读写，对 `chan_cell_meas` 读与 `chan_soc` 写均应使用有限超时（建议 ≤ 50ms，与现状一致）。
- **EARS（普遍）**：系统的工作线程优先级应低于（数值大于）protection 安全线程优先级，确保安全评估不被 SOC 计算抢占或拖延。
- **理由**：SOC 为非安全关键，绝不能因背压或长阻塞拖累更高优先级的安全线程（迭代计划 §4 失效安全 2）。
- **验收准则**：
  1. 读/写 zbus 的超时为有限值（非 `K_FOREVER` 形式的无限阻塞用于数据读写路径）。
  2. SOC 线程优先级数值 > protection 线程优先级数值（即更低优先级）。
  3. 当 `chan_soc` 发布超时，系统丢弃本次发布并继续处理后续帧，不死锁、不无限重试。

## 3. 边界与非功能需求

### REQ-SOC-C10　定点积分防溢出
- **EARS（普遍）**：系统应保证长时间连续运行下电荷累计不发生整型溢出——累计量（量纲 mA·ms）应以至少 64 位有符号整型承载。
- **理由**：mA × ms 累加，`int32` 在小时级即溢出（迭代计划 §4 R1）。
- **验收准则**：
  1. 以最大合理电流（量级由设计给出，建议覆盖 ±100A 即 ±100000mA）连续积分 ≥ 24 小时的等效输入序列，累计中间量不溢出、SOC 计算结果正确且夹紧正常。
  2. 设计阶段须给出量纲推导与溢出边界证明（本需求在此处置追溯位）。

### REQ-SOC-C11　精度与容差
- **EARS（普遍）**：系统的库仑积分在不触发夹紧的工作区间内，对解析期望 SOC 的稳态误差应 ≤ ±1‰（受 ‰ 量化与定点舍入限制）。
- **理由**：明确可量化的精度验收判据，便于测试设定容差（迭代计划 §2 准出「明确数值容差」）。
- **验收准则**：
  1. 恒流定时序列下，实测 SOC 与解析 SOC 之差 ≤ ±1‰。
  2. 多步小增量累加的舍入误差不应单调累积到超过容差（设计阶段定义舍入策略，测试验证 N 步后误差仍 ≤ 设计上限）。

### REQ-SOC-C12　额定容量可配置
- **EARS（普遍）**：系统的安时积分换算应基于一个可配置的电池组额定容量（单位 mAh），不得在算法中硬编码不可配的容量数值。
- **理由**：换算依赖额定容量，硬编码不利于多板型/多电池适配（迭代计划 §4 R4）。
- **验收准则**：
  1. 存在一个表征额定容量（mAh）的配置项（命名/默认值由架构/设计阶段确定，例如 `CONFIG_BMS_SOC_PACK_CAPACITY_MAH`）。
  2. 改变该配置值，相同输入序列下 SOC 增量按 `1/容量` 比例变化，符合 REQ-SOC-C01 验收公式。

## 4. 非目标边界（需求层面显式排除，防夹带）

下列项在本迭代**不**产生功能需求（仅占追溯位，沿用桩/常量），与迭代计划 §1 非目标一致：
- SOH 估算：`soh_permille` 固定 1000‰。
- 卡尔曼/OCV 开路电压校正、温度补偿、自放电、库仑效率建模：本迭代不实现，仅允许预留接口位，不得夹带实现。
- 上电初值的精确 OCV 标定：本迭代用一次性电压映射初始化（REQ-SOC-C04）即可。

**验收**：交付物中不得出现上述任何项的实际功能实现；评审据 §1 非目标核对。
