# S16100B 固件需求规格（逆向提炼）

> 本目录是对 `S16100B_Demo` 现有 BMS 固件的**逆向需求提炼**——即从代码实现反推"系统做了什么"，
> 并以需求工程语言（`REQ-<域>-NNN` + EARS 句式 + 可度量验收准则 + 源码回链）重述。
> 适用场景：补齐历史固件的需求基线、为重构/移植（如新 Zephyr 固件）提供需求输入、作为评审与测试依据。

## 提炼方法

- **范围**：`Application/` 应用层 + `Core/Src` 工程核心 + `Driver/**/*.h` 驱动对外接口。
  驱动实现（`.c`）已封装为静态库 `S16100B_Driver.lib`，**不在发布包内**——凡逻辑落在库里、头文件无法确认的，相关需求标 `状态=存疑`。
- **手法**：按主循环的任务编排划分 12 个功能域，逐域精读源码提炼。
- **忠于代码**：描述代码"实际"行为；代码缺失但显然应有的标 `缺口`；注释与代码矛盾/疑似 bug 的标 `存疑` 并在风险清单展开。
- 格式约定见 [_FORMAT.md](_FORMAT.md)。

## 系统概览（来自 main.c 主循环）

单核裸机轮询架构（STM32F405，168MHz）。主循环依次执行：ADC 采集 → AFE 采集/平滑/保护/断路/负载/均衡 →
统计 → SOC → 告警与保护码 → 加热控制 → 上位机命令 → MOS 控制 → LED → 日志(flash 20s / SD 2s) → 参数存储 → 升级。
工作状态机：断开 → 预充 → 待机 → 充电/放电 → 保护 → 关机。失效安全总则：上电默认断开所有 MOS。

## 已知局限

1. 驱动库源码不可见，AFE 采集/均衡/断路判据、计算等底层算法的精确实现无法核实。
2. 源码原为 GBK 编码，提炼基于 UTF-8 转码副本，未改动原工程。
3. 本批为"实现即需求"，**不代表设计应然**——其中标注的缺口/存疑项需产品/安全负责人裁定，不应直接当作"已确认的产品需求"。
